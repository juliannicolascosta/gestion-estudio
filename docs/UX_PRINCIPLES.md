# Principios de experiencia

## Las Ubicaciones del Estudio son el punto de partida

La navegación comienza en una o varias ubicaciones reconocibles que agrupan los casos. “Ubicación del Estudio” reemplaza términos técnicos como carpeta raíz o carpeta madre. Sumar otra ubicación es opcional: una sola sigue siendo suficiente.

## Buscar en conjunto, actuar en contexto

El buscador consulta todos los casos sin obligar al usuario a recordar si están en el disco local, una red o Google Drive. La ubicación seleccionada determina dónde se crea el próximo caso y qué Acceso rápido se muestra, para que cada acción tenga un destino evidente.

## Una carpeta por caso

No se crean subcarpetas automáticamente. Si el usuario las necesita o un caso ya las contiene, se muestran junto con sus archivos en el mismo panel, sin obligarlo a cambiar de pantalla.

## Los modelos parten de los datos ya cargados

El profesional elegido arriba y los metadatos del caso completan la presentación inicial del escrito. La carátula se construye de forma uniforme y el modelo sigue siendo un Word editable por el usuario.

## Leer primero, editar con intención

Los datos de un caso abierto no cambian por escribir o presionar `Tab` accidentalmente. La ficha se habilita mediante **Editar datos**, separa Guardar de Cancelar y advierte antes de abandonar cambios pendientes. Los datos menos cotidianos viven en **Más datos**.

## Buscar antes que navegar

El buscador encuentra por nombre de carpeta y por los datos del caso. El usuario no necesita recordar dónde guardó cada caso ni recorrer árboles profundos.

## Arrastrar en ambas direcciones

Los archivos pueden entrar desde el sistema o salir hacia correo y otras aplicaciones. Arrastrar desde Archivos del caso hacia la compilación es el gesto principal.

## Lo cotidiano permanece a la vista

DNI, matrícula, CBU y constancias viven en Acceso rápido, sin mezclarse con los casos. La biblioteca no exige abrir otra ventana y permite arrastrar hacia un caso, una compilación o un correo.

## Normalizar con control

La app propone un nombre y, cuando corresponde, convertir a PDF. El usuario ve y puede cambiar la decisión antes de copiar.

## El orden visible es el orden final

La compilación se lee de arriba hacia abajo. El escrito nuevo se agrega al final por defecto, pero puede reordenarse como cualquier elemento.

## El nombre acompaña al archivo fuera de la app

El PDF debe seguir siendo reconocible después de pasar por Xólido. Al compilar se propone `ACTOR_FECHA_TÍTULO`, con confirmación breve y editable. Una recompilación reemplaza de forma consciente o crea una versión numerada explícita.

## Dos archivos, dos propósitos

El Word es el original editable; el PDF compilado es el archivo para firmar o presentar. La interfaz explicita esos estados y evita generar copias auxiliares permanentes o subcarpetas automáticas.

## Teclado para lo cotidiano

`Enter` abre, `F2` renombra y `Supr` quita. Cuando `Supr` actúa sobre un archivo real, siempre hay confirmación y se usa la Papelera para que la acción sea recuperable.

## Comprimir sin destruir intención

El usuario elige el límite antes de compilar. La app intenta comprimir y sólo divide si todavía se excede y el usuario lo confirma.

## Lenguaje jurídico, no informático

Usar Estudio, caso, escrito, documental, compilar, firmar y límite. Ocultar términos internos de archivos, conversión y librerías.

## Iconos para reconocer; texto para decidir

Los gestos rutinarios como volver, abrir, quitar o reordenar pueden usar iconos simples con ayuda emergente. Las decisiones principales —Nuevo caso, Escrito, Compilar PDF y Firmar— conservan palabras claras para evitar ambigüedad.

## Una pantalla y un flujo

Selección de caso → datos y archivos → documental ordenada → compilación → firma. Los diálogos sólo resuelven decisiones puntuales.
